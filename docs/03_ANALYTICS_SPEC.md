# 七格收集三消分析口径

优先级：U1

## 数据链路

参数配置 → 单局状态机 → 事件日志 → 关卡汇总 → 策略/广告档对比 → 设计决策。

## 关键事件

| 事件 | 触发 | 必要字段 |
|---|---|---|
| `level_start` | 新局开始 | 关卡、seed、初始金币 |
| `tile_selected` | 成功点击入槽 | 牌 ID、符号、层数、是否形成三消 |
| `prop_used` | 洗牌或撤销成功 | 道具、成本 |
| `ad_offer` | 失败且仍有广告次数 | 失败原因 |
| `ad_declined` | 玩家拒绝广告 | 失败原因 |
| `ad_completed` | 广告完成并救援 | 返回牌数、补偿步数 |
| `coins_earned` | 通关奖励 | 金额、来源 |
| `coins_spent` | 道具扣费 | 金额、去向 |
| `prop_unaffordable` | 想用道具但金币不足 | 道具、所需金币 |
| `level_end` | 成功或最终失败 | 结果、失败原因 |

## 指标定义

- **通关率**：`result = won` 的局数 / 总局数。
- **平均操作数**：每局成功点击入槽的牌数平均值。
- **七槽溢出率**：因 `slot_overflow` 最终失败的局数占比。
- **广告提供率**：至少出现一次 `ad_offer` 的局数占比。
- **广告接受率**：`ad_completed / ad_offer`。
- **救援后通关率**：至少救援一次的局中，最终通关的占比。
- **零币率**：局末或关卡链统计点金币为 0 的局数占比。
- **道具买不起概率**：至少发生一次 `prop_unaffordable` 的局数占比。

## 分析边界

1. 机器人策略不能代表真人决策。
2. 单关独立样本和跨关金币继承样本必须分开。
3. 通关率变化必须同时报告广告提供率和救援后通关率。
4. 金币来源和去向必须分账，不能只报期末余额。
5. 不根据本模型推算 eCPM、广告收入、DAU 或留存。

## 最小验收看板

- 分策略、分广告档、分关卡的原始汇总表。
- 通关率曲线。
- 七槽溢出率与广告接受率。
- 金币来源、消耗、期末余额和买不起事件。
- 可下载 CSV，字段可复算。
